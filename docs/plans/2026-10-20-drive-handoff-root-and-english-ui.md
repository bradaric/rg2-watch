# Drive Handoff Root and English UI Implementation Plan

> **For agentic workers:** REQUIRED: Use subagent-driven-development (if subagents available) or executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recover the failed first Google Drive case publication under a single private `RG2 Watch` folder and make the local case-handoff controls and errors English, while keeping the public case and Viber text in Serbian Cyrillic.

**Architecture:** Extend the existing `DrivePublisher` and Drive adapter, not the watcher. One app-managed, private Drive root is shared by all election databases using the same OAuth token **and verified Google account**; an ignored token-adjacent state file records its preallocated Drive ID, creation phase, and account identity under a cross-process lock. New case folders are created under it. For the already stranded empty case folder, an explicit setup command creates the private root; the operator verifies the case folder is empty and manually moves it into that root before retrying. Publication then reconciles the original folder ID and frozen package, with no automatic migration. Only the case folder receives public access after both files upload; existing URL-specific locks remain unchanged.

**Tech Stack:** Python 3.12, existing SQLite/Google Drive v3 adapter and OAuth `drive.file`, vanilla JS local page, pytest fake-Drive and UI tests.

## Scope and safety

- Operator-reported state (not independently verified): `data/election-677084.sqlite` has a pending publication; Drive appears to contain an **empty** `RG2 предмет — Књажевац БМ 61` case folder directly in My Drive. The reported error was `remote file metadata does not match the frozen case`. `drive_publish.py` expects `parents=[]` for that folder, whereas a My Drive root-level folder has the root parent ID. Treat these as hypotheses to confirm via the pending row/Drive metadata at explicit recovery, not as facts to hard-code or reasons to weaken checks.
- Desired layout: My Drive / **RG2 Watch** (private) / individual case folders (only explicitly published case folders are `anyone` / `reader`). There is one app-managed root per configured Google account/token, **shared across election databases**, not one per election. No per-election subfolders.
- The root must never be intentionally link-shared by the app. Before making a case folder public, verify the root is app-managed, has the expected name/type, is in My Drive, belongs to the authorized Google account, and has no `anyone` permission; fail closed if modified or inaccessible. Do not move an already-published case, change an existing public link, or alter unrelated Drive items with the same name.
- Account binding: call Drive `about.get(fields="user(permissionId)")` under the existing `drive.file` scope. Treat missing/empty identity as an error. Record that stable ID in root state and on **new** publication claims, before preallocating any remote IDs. Every publish/retry compares current identity to both records before `files.get`, root creation, upload or sharing. A re-run of `drive-auth` with another account at the same token path must fail closed, not create a new root; no automatic account-switch or root reset. For an older pending row without an account ID, bind it **only if** the preallocated case folder is readable with `files.get(...owners(permissionId)...)`, the file's sole owner matches `about.get` and the folder ID/name/type match that row; persist the binding before proceeding. If inaccessible/missing or ownership cannot be established, stop and require manual investigation—do not interpret 404 as an uncreated folder or silently bind a different account. Completed historical publications are read-only and may still display their stored links without Drive mutation.
- Existing pending case: the **operator** will inspect the folder in the Google Drive UI, verify it contains no files, run the one-time root setup command below, and move that same folder manually into the new private `RG2 Watch` root. The app must not claim that `files.list` under `drive.file` proves emptiness; it does not automatically move or publish an unexpected root-level folder. On retry, look up the original preallocated `folder_id` in the pending row, verify its bound account, expected name/type, sole parent **equal to the registered root ID**, private permissions and frozen inputs, then upload. If still under My Drive or elsewhere, fail with an English instruction to verify emptiness/move it manually. If any app-visible unexpected child is present, fail (but absence of app-visible children is not proof of emptiness; the operator must confirm this immediately before publishing). No new folder ID or automatic adoption.
- New cases create the preallocated folder directly with `parents=[root_id]`. Child PDFs/text stay inside it. Folder parent verification compares the **actual expected root ID**; do not special-case all root-level folders as acceptable for normal publication.
- All operator-facing case-handoff panel text is English: buttons, checkbox warning, textarea accessible label, progress, pending/retry, copy feedback, success and error prefixes. The internal review UI elsewhere remains unchanged. The editable public summary/manual template, Drive case text and generated Viber message remain Serbian Cyrillic. Do not expose raw provider errors or credentials when translating UI errors. The separate `AI draft failed; use the manual template` problem is not diagnosed or fixed by this plan.
- Preserve no automatic Viber send, no RIK re-download, current verdict/share ordering, frozen-input retries, same-origin local endpoints, and the existing one-publication-per-document-URL guarantee. No live Drive writes in automated tests. After implementation, an **operator-initiated** live retry is needed to validate Google policy and actual inherited access before sending a link.

## Files and boundaries

- Modify `src/rg2watch/drive_publish.py`: Drive account identity and root adapter methods, case folder create/reconciliation, exact parent/permission verification. No automatic move.
- Create `src/rg2watch/drive_root.py`: one private root ID/phase/account state file and `flock` (path derived from resolved `cfg.drive_token_path`, so separate DBs for one token share it), durable preallocation/creation/recovery. No token bytes in this state file.
- Modify `src/rg2watch/store.py`: nullable publication `drive_account_id` migration and account binding; read-only completed rows remain compatible.
- Modify `src/rg2watch/cli.py`: add a one-time `rg2watch drive-root --config rg2watch.toml` setup command that creates/reuses the private root and prints its Drive folder link; pass root state/token path to publishers for both `watch` and `serve`; no OAuth browser during setup or startup. An unconfigured root must yield a setup instruction rather than implicit creation from a failed case retry.
- Modify `src/rg2watch/static/index.html`: English-only case-handoff controls, warnings, success and error UI; keep Serbian generated text unmodified.
- Modify `tests/test_drive_publish.py` and `tests/test_publish.py`: fake Drive with My Drive parent and a simulated **operator** reparenting, recovery and cross-DB concurrency, UI localization and retry tests.
- Modify `README.md` and `rg2watch.example.toml` only as needed to explain the shared root and operator-initiated live check. Root-state file lives under already ignored `data/`; no new secret files in Git.
