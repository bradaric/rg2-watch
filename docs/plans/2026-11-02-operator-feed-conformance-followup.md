# Operator Feed Conformance Follow-up Implementation Plan

> **For agentic workers:** REQUIRED: Use subagent-driven-development (if subagents available) or executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Repair the reset and NULL-model defects found after the first operator-feed fixes and prove the previously promised concurrent migration, bootstrap, browser and invalidation guarantees.

**Architecture:** Genuine browser resets clear the rendered table and version registries without issuing feed tombstones, and an epoch fences old asynchronous responses. Transactional coverage projections use collision-free tagged model identities so SQLite cannot create duplicate NULL-model counts. Deterministic interleaving tests run real feed/server/browser flows, including process-level migration, bounded bootstrap and snapshot races.

**Tech Stack:** Python 3.12, SQLite/WAL, pytest, multiprocessing/subprocess, existing Node and headless Chromium harnesses, vanilla JavaScript/DataTables.

Do not create/use worktrees, push, deploy, open/migrate the live election DB, restart the watcher, or make live RIK/model calls. Use disposable databases and fake boundaries. Preserve public-results export and localhost security. This is a conformance follow-up, not approval for deployment. Commit implementation only after tests; report residual limitations rather than claiming coverage not run.

**Files and responsibilities:**
- `src/rg2watch/static/index.html`: reset without synthetic tombstones, epoch fencing, persistent group revision/tombstone registry, full-snapshot ordering.
- `src/rg2watch/store.py`: tagged NULL-safe winner/count uniqueness, atomic migration/rebuild/backfill and trigger parity, retained group revisions.
- `src/rg2watch/analysis_selection.py`: one canonical model tie comparator shared by full and selective fallback selection; equal coverage orders empty string before NULL.
- `src/rg2watch/operator_feed.py`: bounded bootstrap and feed snapshot consistency if race tests reveal defects; otherwise leave logic unchanged.
- `src/rg2watch/server.py`: actual HTTP 413 and bound behavior if boundary tests reveal defects; otherwise leave security/handler logic unchanged.
- `tests/test_browse.py`: actual JS async loader/DOM state tests (not helper-only).
- `tests/test_store.py`: NULL-model parity, multi-process migration, table-driven invalidation.
- `tests/test_operator_feed.py`, `tests/test_server.py`: deterministic paging, feed, size-bound and HTTP tests.
- `docs/benchmarks/2026-11-01-operator-feed.md`, `docs/runbook.md`: update only if measurements or operator-visible failure behavior change.

Test a reset while a previous page/feed/snapshot promise is outstanding; old response must be ignored. Demonstrate the current failure before editing the page.
- [ ] Separate `clearRenderedGroups()` from `applyFeedGroups(groups, tombstones)` in `static/index.html`. On a real reset increment `bootstrapEpoch`, invalidate prior feed/bootstrap/snapshot responses, remove DataTables rows directly (or recreate the table without changing filter/search/paging state), set `rows=[]` and `D.rows=[]`, and clear `groupRevisions`/`deletedGroupRevisions` **without calling mergeGroupState or recording tombstones**. Do not synthesize `changed_revision` from `(known || 0)+1` for any server event: reject/handle malformed missing-revision tombstones at the protocol boundary, not by inventing a durable deletion. A reset during an active bootstrap must invalidate that request, then begin a new bootstrap once it is no longer busy; no lost reset due to the `bootstrapBusy` guard. Keep a terminal HTTP 413 state terminal until explicit operator action rather than starting a hidden retry.
- [ ] Test form resets from generation mismatch, order signature change and expired journal `reset_required`. **Distinguish tally snapshot failures:** on initial startup with no valid form table, missing/corrupt `data.json` or `data-meta.json` starts form bootstrap; after valid feed-backed forms exist, a missing, corrupt or mismatched snapshot pair must **not** clear rows, bump epoch or clear `groupRevisions`/`deletedGroupRevisions`. ### Task 2: Make the projection correct for NULL analysis models

- [ ] First add failing tests in `tests/test_store.py` for two eligible documents each with a completed `model=NULL` analysis, plus competing named-model analyses: projected `operator_model_counts(parent)` must equal legacy `operator_model_coverage(parent, PROMPT_VERSION)` and `preferred_models()` ordering. Test direct SQL insert/update (`NULL` to named, named to `NULL`, document ID change), delete, analysis version replacement, document parent/type change, deletion, repeat Store open and two election parents. Include the case where one analysis update runs both `pick_old` and `pick_new`. Record red results before modifying schema.
- [ ] In `tests/test_browse.py` and `tests/test_operator_feed.py`, add failing parity tests for **equal-coverage `None`, `""` and named fallback models**: configured preferred model remains first; among equal coverage, the canonical comparator sorts named strings lexicographically (so `""` comes before nonempty names) and sorts `None` **last**. Check repeated fresh Stores and separate processes produce the same full-builder fallback selection, selective row selection and `model_order_signature` regardless of SQLite row order or insert order. Add `analysis_selection.py` to the implementation scope: define a single pure `model_tie_key(model: str | None) -> tuple[bool, str]` returning `(model is None, model or "")`; use it in `preferred_models()` **and** `preferred_analyses()`'s appended-model sort, and in `operator_feed.effective_model_order()` for identical count/name tie-breaking. The projection count query should also use deterministic tagged ordering (`ORDER BY model_is_null, model_value`) rather than relying on SQLite's unspecified row order. Do not coalesce `None` and `""` or change count priority; do not expand the configured-model API to accept NULL merely for this test.
- [ ] Replace nullable composite projection keys with explicit tagged non-null columns (e.g. `model_is_null INTEGER NOT NULL CHECK(model_is_null IN (0,1))`, `model_value TEXT NOT NULL` where null uses `(1,'')` and a named model uses `(0,original_value)`). Winners are unique on `(document_id, model_is_null, model_value)` and counts on `(parent, model_is_null, model_value)`; decoding maps `(1,'')` back to Python `None` and does not conflate it with a real empty-string model `(0,'')`. Make every trigger compare tagged keys rather than nullable equality, including `pick_old`/`pick_new`; prevent duplicate winners/counts on UPDATE. Count adjustments remain in the originating data transaction and do not introduce election-wide scans on normal writes/reads.
- [ ] Version the existing `operator_model_projection_meta` so a single `BEGIN IMMEDIATE` migration rechecks the marker, drops/recreates affected versioned triggers and projection tables, backfills winners/counts from eligible legacy analyses, and writes the new marker **last** before commit. Keep the dependency-neutral `PROMPT_VERSION` owner; prompt-version changes still rebuild the projection/trigger SQL. Do not use `executescript()` inside the migration transaction or touch any unrelated production tables. Test migration from the previous projection schema using a disposable fixture and verify second open does not rebuild, failed backfill rolls back, and old/new parent coverage matches the legacy query.
- [ ] Run `uv run pytest -q tests/test_store.py tests/test_operator_feed.py tests/test_browse.py`; trace ordinary count reads to confirm O(number of models) and normal feed polling still does not scan election-wide analyses.

## Chunk 2: Prove migration, paging and feed ordering under races

### Task 3: Prove process-level migration serialization

- [ ] Write a **two-process** disposable-database test in `tests/test_store.py`. One opener enters `BEGIN IMMEDIATE`, reads the old projection marker and pauses **inside** that transaction before rebuilding; a second process attempts Store construction and must wait rather than read partial projection state. A separate read-only observer sees only the old committed state until the first commits; after release, both openers return identical counts/marker/trigger SQL. Instrument rebuild/backfill entry with an IPC counter: exactly one process commits a rebuild. Use pipes/events and bounded timeouts with `finally` cleanup; no sleeps as synchronization and no live DB. Include a failing/rolled-back first opener so the second can complete a single correct rebuild.
- [ ] If the existing initialization order or SQLite busy timeout prevents the above guarantee, change only the migration boundary and add tests for normal/retry behavior; do not claim that a two-thread barrier *before* migration proves cross-process exclusivity. Run the targeted test repeatedly and `uv run pytest -q tests/test_store.py`.

### Task 4: Exercise real 102+-group bootstrap and exact HTTP size edges

- [ ] In `tests/test_operator_feed.py`, use at least **102 tagged groups** so a second page is forced. Pause after page 1 at revision `R`; before page 2 perform, in separate deterministic cases: review on page 2, insert before cursor, delete after cursor, station-to-document move, write during one page's read transaction, and prune past floor. Drain all pages then journal replay from `R`; compare the final tagged groups to a fresh full read. Verify returned group revisions never label post-`R` contents `R`, rows/tombstones aren't lost or duplicated, no read transaction spans HTTP requests, and floor overrun resets rather than silently skipping.
- [ ] In `tests/test_server.py` send **real** `/operator-bootstrap` requests with a disposable group containing enough historical versions to straddle `BOOTSTRAP_BYTES` and the actual `OPERATOR_MAX_BYTES` after encoding the *entire envelope/cursor* via `json.dumps(..., ensure_ascii=True).encode()`. Construct payload sizes dynamically around the measured threshold (immediately below/above, including escaping/non-ASCII) rather than approximate MB constants. A group over the soft limit but below hard limit arrives intact on one page. A group above hard limit returns typed HTTP 413 from the real feed and leaves the browser in visible terminal failure, not a retry loop; an earlier page never advances past the omitted unchanged group. Assert endpoint security constraints and no response exceeds the hard cap.
- [ ] If a test is red, fix only the corresponding paging/HTTP path; keep the page's short read transaction, cursor signature verification, tagged identities, and selected-group replay. Run `uv run pytest -q tests/test_operator_feed.py tests/test_server.py`.

### Task 5: Prove feed `T`/`T+1` and tombstone persistence

- [ ] In `tests/test_operator_feed.py`, distinguish two bounded-feed interleavings: (a) select entries through `T` inside an already-pinned SQLite read snapshot, pause, then commit a same-group write at `T+1` through a second Store; the current response must contain only the **pre-write** row/tombstone at `T`, with `through=T`, and the next poll from `T` must deliver the write. (b) commit `T+1` **before** pinning the read view but bound selection to a chunk ending at `T` (add later journal entries/groups so the chunk is genuinely limited); the selected group may be assembled at its durable current `changed_revision=T+1` while `through` remains `T`, and replay from `T` must be idempotent. Include row-to-tombstone, delete/re-create, analysis replacement, and an older full snapshot. Never demand that one SQLite snapshot observe a commit made after its read view was pinned. Use barriers/events, not timing sleeps; keep server response limits.
- [ ] In `tests/test_browse.py`, use actual `mergeGroupState` plus mocked table/DataTables `rows().remove()` and `applyFeedGroups()` across multiple snapshot and feed responses. Test both orderings: stale row after revision-10 tombstone does not resurrect, and stale tombstone after revision-10 row does not remove. A revision-11 re-create must work; equal revisions cannot undo a deletion; an older full snapshot must not erase registry entries. Keep per-tag revision state across normal redraws, clear it only on genuine epoch reset. Fix code only if tests expose a defect.
