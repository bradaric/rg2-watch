# Operator Feed Review Fixes Implementation Plan

> **For agentic workers:** REQUIRED: Use subagent-driven-development (if subagents available) or executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Correct the five plan-conformance findings on the merged fast operator forms feed so ongoing analyses remain selective, bootstrap and full snapshots cannot regress newer state, and the critical races are tested.

**Architecture:** Store maintains transactional per-document/model winners and election/model coverage counts; reads derive the effective fallback order from these small counters. Feed, bootstrap and full snapshots carry an order signature in addition to their existing generation and revision; a changed signature triggers browser rebootstrap, replacing coarse global journal entries for model coverage. Bootstrap pages use short consistent read transactions, skip groups changed after the cursor's original high-water, and replay the journal. Browser snapshot application is serialized and monotonic by generation, revision and snapshot ID.

**Tech Stack:** Python 3.12, SQLite/WAL triggers, existing `http.server`, vanilla JavaScript/DataTables, pytest, existing Node browser harness.

## Chunk 2: Correct paging and revision labels

- [ ] In `tests/test_operator_feed.py`, write a deterministic 102+-group interleaving: read page 1 at revision `R`; write a review for a group on page 2; assert page 2 never emits its new review with `changed_revision=R`. After all pages, poll from `R` and assert the changed group is delivered with its true revision and no lost/twice-applied row. Add insert-before-cursor, delete-after-cursor, station-to-document move, a write during the current page's read, and floor-overrun cases. Verify no SQLite transaction stays open between HTTP page requests. Add a large multi-version group whose complete response exceeds `BOOTSTRAP_BYTES` (currently 1 MB) but is below the server's `OPERATOR_MAX_BYTES` (currently 2 MB); it must arrive intact on one page. Add a group exceeding the 2 MB hard limit: request must terminate with a visible error rather than drop rows or retry forever.
- [ ] Keep the signed cursor's start revision, generation, order signature and last visited tagged identity. Each page reads journal high-water, group identities, durable `operator_feed_group_revisions` and rows from **one short read snapshot**. Skip an identity with group revision `> start_revision`; never serialize that identity's current row as if it were from the old revision. Carry the cursor forward past skipped identities, and preserve the page size/byte bound. A group newly inserted earlier than the cursor is recovered through journal replay; a deleted group is replayed as a tombstone. When the journal floor overtakes the start revision, return `reset_required` rather than skipping unseen changes; when generation/order signature changes, restart visibly. Keep the UI in a loading/catching-up state until replay has caught up.
- [ ] Implement **lossless bounded oversized-group handling**: page packing may exceed the soft `BOOTSTRAP_BYTES` only for a *single complete group* that fits inside `OPERATOR_MAX_BYTES` including the final JSON envelope/cursor; when a group cannot fit after earlier groups, return the earlier groups and leave that group for the next page. Never advance the cursor past an unchanged group without returning it. For a group whose complete response exceeds the hard limit, return a typed `operator_group_too_large` HTTP 413 (without leaking report contents), render a visible terminal bootstrap error with recovery instructions, and stop automatic retries for that cursor; no “forms current” label or silent fallback to missing rows. Permit progress past scanned **post-start changed** identities, which are explicitly replayed from the journal, even if they fill an otherwise empty page. For the soft/hard boundary, measure the actual encoded response envelope with the same JSON encoding used by `server.py`; cap the page before writing any bytes. Test both boundaries and a page containing only skipped identities; test previously reported 102-group/review reproduction.
