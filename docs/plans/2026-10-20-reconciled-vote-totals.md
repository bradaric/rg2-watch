# Reconciled Vote Totals Implementation Plan

> **For agentic workers:** REQUIRED: Use subagent-driven-development (if subagents available) or executing-plans to implement this plan. Steps use checkbox (`- [ ]`) syntax for tracking. Do not change source files until this plan is committed and implementation is delegated.

**Goal:** Across all results views and CSV exports, ensure displayed candidate-list votes add to displayed valid votes, retain existing turnout, and disclose invalid votes and any unresolved gap without mislabelling it.

**Architecture:** Make form-level vote reconciliation an eligibility rule in `tally.py`, rather than repairing numbers in the browser. Aggregate the valid field and every candidate-list field atomically, preserving independent turnout aggregation. Add explicit metadata for vote-contributing forms and readable valid fields withheld by reconciliation. Render those values consistently through the existing corrected/as-filed/like-for-like difference paths, hero, tables and CSV.

**Tech Stack:** Python tally and pytest; existing vanilla JavaScript/HTML results page and DataTables; existing generated `data.json` payload. No new dependency or persistence migration.

## Scope and semantics

The user-provided screenshot appears to show 15,364 voters, 14,648 independently aggregated valid votes, and candidate rows 8,187 + 6,377 + 358 + 291 + 110 + 87 = 15,410; those displayed rows sum to nine more than the calculator's 15,401. Verify the actual source-data values before using these numbers as a regression fixture. This plan does **not** assume which source form is wrong and does not change extracted or corrected source readings.

For a form in a known ballot, define **vote-eligible** iff its valid vote field is readable, its list row keys exactly equal that ballot's expected row keys, every list value is readable, and the sum of list values equals its valid field. Apply separately to corrected and as-filed extracts and separately to all and clean selections (the clean selection additionally requires no existing `why`/`why_f` reasons). A form can be flagged for a non-vote reason yet still be vote-eligible in all mode. Do not relabel vote-ineligible as clean/flagged: the latter status already has independent meaning.

In each totals block, `valid == sum(lists) == lists_valid` whenever a ballot's lists exist. Count `invalid` from vote-eligible forms only when that field is readable; an unreadable invalid field does not make otherwise eligible valid/list votes disappear. Keep registered/voted turnout, in-box and outside-voted calculations on their current independent rules. The **signed, unresolved turnout gap** is `voted - valid - invalid` in the same selected view; it is not asserted to equal invalid, blank, uncounted, or the number of rejected ballots. Its sign must be visible, including negative values. When turnout is unavailable for a scope, do not call the number an accounting identity.

Track per-view `vote_forms` (number of selected forms meeting vote eligibility) and `withheld_valid` (sum of *readable* valid fields on selected forms that fail vote eligibility). In corrected/filed views only, show `selected_form_count - vote_forms` as forms not supplying reconciled totals, where `selected_form_count` is `counted` for all mode, `clean` for corrected clean mode, and `fclean` for filed clean mode. `withheld_valid` is explicitly a partial, known amount and may be zero when rejected fields were unreadable. All counts refer to analysed, selected forms, not missing/unanalysed station documents. Empty expected ballot row sets and `(unknown)` mixed municipal ballots are ineligible for reconciled votes; retain the current absence of list rows at `(unknown)` and in municipal all-municipality totals, and mark these scopes as having no comparable list totals rather than implying their sums can be inspected.

For difference view, keep existing `pair` like-for-like behavior: compare only terms eligible on both corrected and filed sides. `valid`, `lists`, and `lists_valid` must enter/leave paired accumulation together; `vote_forms` counts only forms paired for vote terms. Add **pair-selection metadata**, not a subtraction from `counted`, `clean` or `excluded`: `pair_selected` counts forms selected on *both* sides (`take_c && take_f`, namely all counted forms in all mode and the intersection of corrected-clean and filed-clean forms in clean mode); `pair_vote_forms` counts those same forms vote-eligible on *both* sides; `corrected_only_vote_forms` and `filed_only_vote_forms` count forms in `pair_selected` vote-eligible on just one side. `pair_not_contributing = pair_selected - pair_vote_forms`, comprising both one-sided categories and forms ineligible on both. Forms clean on just one side are outside this denominator and continue to be reflected in existing clean/flagged deltas and joined/left term counts. Derive these counters per form in the existing `build_tally` pair loop, aggregate per municipality and overall, and publish on each `pair[mode]` object. Render in difference mode as *actual paired cohorts*, e.g. `Q of P forms selected in both views contributed to compared vote totals; R not paired (X corrected-only eligible, Y filed-only eligible, Z neither)`; do not format these cohort sizes with `dnum`, and do not present `vote_forms` delta (which is zero by definition for paired vote terms) as the cohort size. The corrected/filed `vote_forms` remain ordinary totals. Signed `withheld_valid` and gap in difference mode are differences of comparable paired terms, not observed ballot counts. Since each side's paired lists equal paired valid, their difference does as well. Do not add an invented list row for invalid or missing votes.

Existing `pair[mode].in/out` counters refer to forms with **any contribution terms present on only one side**, not solely to selected forms or vote terms. Keep their calculation and signed counts, but update every explanation (CLI, page, CSV) to say that a correction may change readability, clean/flagged selection, **or vote-reconciliation eligibility**; unmatched terms are omitted from like-for-like differences. Do not call them `stations newly counted/removed` without a clarifying `terms` qualifier: all those forms may already be counted on both sides.
